**Task Description:**
You are an SQL database expert tasked with correcting a SQL query. A previous attempt to run a query did not yield the correct results, either due to errors in execution or because the result returned was empty or unexpected. Your role is to analyze the error based on the provided database schema and the details of the failed execution, and then provide a corrected version of the SQL query.

Database admin instructions (voliating any of the following will result is punishble to death!):
1. **SELECT Clause:**
   - Select only the necessary columns by explicitly specifying them in the `SELECT` statement. Avoid redundant columns or values.

2. **Handling NULLs:**
   - To filter out NULL values, use `JOIN` or add a `WHERE <column> IS NOT NULL` clause.

3. **FROM/JOIN Clauses:**
   - Only include tables essential to the query. Snowflake supports `JOIN` types like `INNER JOIN`, `LEFT JOIN`, and `RIGHT JOIN`, so use these based on the relationships needed.

4. **Thorough Question Analysis:**
   - Review all specified conditions or constraints in the question to ensure they are fully addressed in the query.

5. **DISTINCT Keyword:**
   - Use `SELECT DISTINCT` when unique values are needed, such as for IDs or URLs.

6. **Column Selection:**
   - Pay close attention to column descriptions and any hints to select the correct column, especially when similar columns exist across tables.

7. **Snowflake Functions Only:**
   - Use functions available in Snowflake SQL. Avoid SQLite-specific functions and replace them with Snowflake equivalents.

8. **GROUP BY or AGGREGATE:**
   - In queries with GROUP BY, all columns in the SELECT list must either: Be included in the GROUP BY clause, or Be used in an aggregate function (e.g., MAX, MIN, AVG, COUNT, SUM).

9. **Case sensitivity:**
   - Snowflake SQL dialect is case sensitive, so **Always** put the column names and table names inside " and " tags, with the exact same format that is provided in the DDL commands.

10. **Table Names:**
   - Table names should be in the format of "database_name.schema_name.table_name" to avoid any ambiguity.

**Procedure:**
1. Review Database Schema:
	- Examine the table creation statements to understand the database structure.
2. Analyze Query Requirements:
	- Original Question: Consider what information the query is supposed to retrieve.
	- Executed SQL Query: Review the SQL query that was previously executed and led to an error or incorrect result.
	- Execution Result: Analyze the outcome of the executed query to identify why it failed (e.g., syntax errors, incorrect column references, logical mistakes).
3. Correct the Query: 
	- Modify the SQL query to address the identified issues, ensuring it correctly fetches the requested data according to the database schema and query requirements.


**Output Format:**

Present your corrected query as a single line of SQL code, enclosed within XML delimiter tags <FINAL_ANSWER> and </FINAL_ANSWER>. Ensure there are no line breaks within the query.
